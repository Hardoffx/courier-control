# Courier Control — Pilot Acceptance Checklist

Выполнить перед выдачей пилота реальным пользователям. Детали установки находятся в `PILOT_DEPLOY.md`.

## Application
- [ ] Последний CI на `main` зелёный.
- [ ] `python manage.py check` и проверка миграций проходят.
- [ ] `/healthz/` возвращает исправное состояние приложения и БД.
- [ ] Статика собрана.

## Pilot configuration
- [ ] Debug выключен, настроены secret key, allowed hosts и trusted HTTPS origins.
- [ ] SQLite находится на постоянном диске и каталог staging имеет закрытые права.
- [ ] HTTPS включён до выдачи пользовательских логинов.

## Yandex Maps
- [ ] Настроены JS API и Geocoder API credentials через environment.
- [ ] Browser API credential ограничен фактическим доменом/referrer.
- [ ] Активные точки геокодированы; выборочно проверено не менее 10 реальных адресов.
- [ ] Courier и Dispatcher maps показывают только сохранённые реальные координаты, правильный порядок и статусы.

## Real Excel
- [ ] Проверен настоящий management XLSX без ручной переделки.
- [ ] Preview корректен и не изменяет БД.
- [ ] Тип точки определяется по содержимому/справочнику, а не по цвету строки.
- [ ] Повторный импорт не создаёт дублей; легитимные повторные посещения сохраняются.
- [ ] Канонические адреса и телефоны справочника используются ожидаемо.
- [ ] Истёкший и уже использованный staging token отклоняется.

## Dispatcher
Проверить desktop, tablet и phone: дата/поиск/фильтры; создание и редактирование; single/bulk assignment; RouteRun из шаблона; временная замена курьера без изменения default; разовая точка и порядок; copy previous; explicit template learning; проблемы/history; statistics/CSV; List/Map/Split там, где размер экрана позволяет.

## Courier
Проверить минимум 375, 390 и 430 px: next stop; звонок; внешняя навигация Yandex; completion с GPS и без GPS; problem reason; порядок и состояния маршрута; внутренняя карта; отсутствие координат у части точек; PWA safe-area и нижняя навигация.

## Backup and restore
- [ ] Backup script создаёт читаемую копию SQLite.
- [ ] Выполнено тестовое восстановление на копии/временной БД.
- [ ] После восстановления health check зелёный и тестовый день открывается.
- [ ] Настроен регулярный backup и понятен срок хранения.

## Pilot launch
- [ ] Созданы отдельные реальные аккаунты; demo credentials не используются.
- [ ] Проверено разграничение ролей.
- [ ] Проведён один тестовый день на реальных адресах.
- [ ] Feedback и некритичные ограничения первого дня зафиксированы.

## Stop conditions
Не запускать пилот при красном CI, отсутствии HTTPS, непроверенном backup, ошибочном импорте реального XLSX, нарушении ролей, потере completion/problem данных или отображении непроверенных координат.

После acceptance записать дату, commit SHA, пилотный host, число пользователей и известные ограничения в `PROJECT_STATE.md`. PostgreSQL остаётся отдельным обязательным этапом перед существенной concurrency/full production.
